4.2 Сетка долей
- Прогони beats.py по всему треку и посмотри energy_db_250ms, чтобы найти дроп.
- M0 — сильная доля прямо перед дропом (или такая, чтобы первый большой удар попал в дроп).
- Ставь M0 ровно на сильную долю: тогда B0 = 0 и BB[0] ≈ 0.
- Затем прогони beats.py <трек> M0 <ДЛИНА+2> и запиши ads/video/channel/<slug>.beats.js (window.BEATS = …). Времена считаются от t=0 ролика.

4.3 Звуковые эффекты (SFX)
- Список событий даёт сама страница: window.CUES (п.6.3). Звуки синтезирует sfx.py. Это эффекты, а не музыка, поэтому так можно.
- whoosh — на переходах, tick — на появлениях, hit — на ударах (бас + звон), riser — перед ответом, subdrop — на глитче.
- Громкость: пики SFX примерно на 6 дБ ниже пиков музыки.
- SFX идут в микс до loudnorm и не идут в sidechain.

4.4 Музыка играет вместе с картинкой (всё берётся из CUES, делает mix.py)
- gap: до 0.15 с тишины в музыке перед резким ходом.
- От breath_on до breath_off: low-pass около 700 Гц под «вдохом». Фильтр выключается на доле D (п.3.5).
- К кадру петли музыка затухает.

4.5 Уровни
- Без голоса: музыка −14 LUFS.
- Только SFX (нет ни музыки, ни голоса): −20 LUFS, чтобы трендовый звук в TikTok был громче.
- С голосом:
  - музыкальная подложка нормируется до −19 LUFS ДО приглушения;
  - голос −15 LUFS;
  - под фразами sidechain снимает ещё 8–10 дБ: sidechaincompress threshold=0.05 ratio=4 attack=20 release=350;
  - сильнее не надо: при threshold 0.02 ratio 6 музыка пропадает.
- Итог: двухпроходный loudnorm до −14 LUFS (только SFX — до −20), true peak не выше −1.5 dBTP.

6.2 Инструменты (ads/video/tools/)
Ищи их там: ls ads/video/tools. Если их нет, напиши сам (Python — только numpy + ffmpeg; Node — Playwright) и проверь. Дальше только переиспользуй.
- beats.py <аудио> [start] [dur] → JSON {bpm, beat, offset, beats[], downbeats[], hits[], energy_db_250ms[]}.
  - Метод: лог-спектральный поток + автокорреляция в диапазоне 70–180 BPM + фаза гребёнкой.
  - Важно: выбирай между фазой и фазой + ½ периода по линейной мощности полосы ниже 150 Гц (бочка), а не по лог-потоку: хэты тоже дают поток ниже 150 Гц. Иначе сетка цепляется за хэты и уезжает примерно на 200 мс.
  - STFT сдвигает онсеты примерно на 20 мс раньше: уточняй каждую долю по огибающей с шагом 1 мс.
  - downbeats: из 4 возможных фаз такта бери ту, где больше всего энергии ниже 150 Гц.
  - hits: онсеты, где поток выше медианы + 3·MAD, не чаще одного раза в 90 мс.
  - Проверка: на клик-треке из ffmpeg ошибка не больше 10 мс.
- vo_timeline.py beats.json first_beat gap f1.wav f2.wav … → [{file,t0,t1,dur,beat,delay_ms}].
- cues.js <страница> → cues.json. Открывает страницу в Playwright, ждёт READY и печатает {duration, cues}.
- sfx.py cues.json out.wav → синтез через ffmpeg (aevalsrc, anoisesrc + фильтры):
  - whoosh: шум через полосовой фильтр, огибающая на dur (0.2–0.4 с), пик −12 dBFS;
  - tick: синус 2–4 кГц, 20–40 мс, пик −18 dBFS;
  - hit: синус 120→45 Гц 0.3 с + короткий шумовой «звон», пик −8 dBFS;
  - riser: шум + синус 200→3000 Гц на dur, с нарастанием, пик −14 dBFS;
  - subdrop: синус 60→30 Гц 0.6 с, пик −8 dBFS.
- mix.py video.mp4 <music.mp3|none> M0 out.mp4 [--vo vo.json] [--sfx sfx.wav] [--cues cues.json] [--nomusic]
  - отрезок музыки с M0 на длину видео, fade-in 30 мс, fade-out 1 с к концу;
  - по cues: gap → музыка на 0 в этом окне; от breath_on до breath_off → lowpass около 700 Гц;
  - уровни из п.4.5; SFX добавляется до loudnorm, мимо sidechain;
  - --nomusic: голос + SFX до −14 LUFS; если голоса нет — только SFX, −20 LUFS (п.4.5);
  - двухпроходный loudnorm I=<цель> TP=-1.5 LRA=11 linear=true. Если пик выше громкости больше чем на ~11 дБ, linear молча превращается в dynamic: сначала мягко срежь пики alimiter-ом и измерь снова. Печатай режим loudnorm — он должен быть linear;
  - затем alimiter limit −1.8 dBFS, level=0 (предел −1.5 по сэмплам не гарантирует −1.5 dBTP; без level=0 он сам меняет уровень);
  - затем aresample=48000 (loudnorm внутри работает на 192 кГц);
  - AAC 192k с -cutoff 18000 (без него пики AAC вылезают примерно на 2 дБ);
  - видео копировать без перекодирования;
  - в конце печатать проверку ebur128=peak=true.
- fontcheck.js <страница>: проверяет шрифты как в п.6.3 и печатает результат по каждому весу.
- textcheck.js <страница>: проверяет зоны текста (п.7).

6.3 Контракт страницы
- Каркас: <meta name="viewport" content="width=1080">; body{width:1080px;height:1920px;overflow:hidden;margin:0;background:#0A0A0E}. Все размеры в px.
- Самый первый скрипт в <head>: <script>window.READY=false</script>.
- Данные подключай так: <script src="<slug>.beats.js"></script> и <script src="<slug>.vo.js"></script>. fetch локальных файлов не работает.
- Время пиши в долях:
  const BB=BEATS.beats, BP=BEATS.beat;
  const TB=b=>{const n=BB.length-1,i=Math.floor(b);if(i<0)return BB[0]+b*BP;if(i>=n)return BB[n]+(b-n)*BP;return BB[i]+(BB[i+1]-BB[i])*(b-i)};
  const BT=t=>{const n=BB.length-1;if(t<=BB[0])return(t-BB[0])/BP;if(t>=BB[n])return n+(t-BB[n])/BP;let i=0;while(BB[i+1]<=t)i++;return i+(t-BB[i])/(BB[i+1]-BB[i])};
  const B0=BB.indexOf(BEATS.downbeats[0]);
  const HIT=k=>Math.floor(TB(k)*30)/30-0.025;   // время удара в кадре: на доле или раньше, с запасом под MB=4
- Длина задаётся синхронно и из долей: const BARS=<ДЛИНА / длина такта, округлённая до целого>; window.DURATION=TB(B0+4*BARS);
  - Не длиннее отрезка музыки и не больше 40 с.
  - Числом вручную не пиши.
- window.CUES — массив, считается один раз при загрузке страницы из TB и HIT: [{t, type, dur?}].
  - type: whoosh, tick, hit, riser, subdrop, gap, breath_on, breath_off, free.
  - t — начало звука. Для tick, hit и subdrop t = сама доля TB(k), а не HIT(k): звук раньше доли больше чем на ~45 мс уже заметен.
  - whoosh: t = начало движения, пик звука — на 60% dur. riser: t = TB(удара) − dur, он нарастает до удара. gap: тишина в [t, t+dur], ставь так, чтобы t+dur = TB(удара).
  - free {t, dur} — окно, где текст может уходить за зоны: вылет, пролёт сквозь камеру, crash zoom. Ставь его на каждый быстрый уход текста, иначе кадры смаза засчитаются как нарушения.
- window.TEXTBOX — заполняется на каждом seek: рамки текста, нарисованного на canvas (частицы-буквы, сборка ответа): [{x0,y0,x1,y1,text}].
- window.seek(t) — чистая функция от t:
  - ограничь t диапазоном [0, DURATION];
  - на каждом вызове задавай всё: opacity, transform, filter, текст, display; каждый canvas полностью очищай и перерисовывай;
  - порядок вызовов не должен влиять на кадр.
- Запрещено: таймеры, requestAnimationFrame, CSS transitions и animations, <video>, Date.now, performance.now, Math.random, состояние с прошлого кадра.
  - Случайность — только rng(seed). Зерно выбирай по floor(t*30).
  - Кэшировать ссылки на DOM-элементы можно, если результат seek(t) от этого кэша не зависит.
- Шрифты:
  - подключение: <link href="https://fonts.googleapis.com/css2?family=Onest:wght@300;400;500;600;700;800&display=swap" rel="stylesheet">;
  - для каждого используемого веса: const r = await document.fonts.load('700 120px Onest', '<все реальные строки с экрана + цифры>'). Массив r должен быть не пустой;
  - потом await document.fonts.ready;
  - потом для каждого веса W должны быть true оба условия: [...document.fonts].some(f=>/Onest/.test(f.family)&&String(f.weight)===String(W)&&f.status==='loaded') и document.fonts.check(...). Иначе throw;
  - не прячь ошибку в try/catch: check() бывает true, даже когда шрифт вообще не подключился;
  - если Google Fonts не грузится: скачай CSS с fonts.googleapis.com через curl с заголовком браузера (-A 'Mozilla/5.0 … Chrome/120'), возьми из него ссылки на woff2 (fonts.gstatic.com), положи файлы в ads/video/channel/fonts/ и подключи через @font-face. Эти хосты обычно открыты; если нет — попроси их (как во вступлении).
- После шрифтов: build() (замеры DOM и частицы из текста — только после загрузки шрифта) → seek(0) → window.READY=true.
- Режим ?debug=1 показывает вспышку-метку на каждой доле (для проверки синхрона).
- Слои, снизу вверх:
  1) canvas фона;
  2) div сцены (perspective:1600px, CSS 3D);
  3) canvas эффектов (сложение 'lighter');
  4) div вспышки (plus-lighter);
  5) виньетка;
  6) canvas зерна (opacity около .055).
- Помощники бери из ads/video/scene-a.html: clamp, lerp, P, E, spring, decay, rng, S, TR, words, blob, softRing, sparkle, streak, dotCorridor, waveMesh, sample, spd, flashA, drawGrain.
  - Нужное скопируй в новый файл: страница должна быть самодостаточной.
  - Не копируй ENG и svgE (там чужие логотипы) и try/catch вокруг загрузки шрифтов.

6.4 Рендер
- Всегда передавай 1080 1920 30: по умолчанию стоит 1920x1080, и кадр обрежется. Команды запускай из корня репозитория.
  - Черновик: node ads/video/render.js 'ads/video/channel/<slug>.html?debug=1' <tmp>/draft.mp4 1080 1920 15
  - Кусок со смазом: MB=4 node ads/video/render.js ads/video/channel/<slug>.html <tmp>/sec.mp4 1080 1920 30 8.0 12.5
  - Финал: MB=4 node ads/video/render.js ads/video/channel/<slug>.html <tmp>/final_silent.mp4 1080 1920 30 (около 40 с работы на 1 с ролика: 30 с ≈ 20 мин; черновик ≈ 3 мин)
  - Сжатие для TikTok (render.js пишет CRF 18, с зерном это 100+ МБ): ffmpeg -i <tmp>/final_silent.mp4 -c:v libx264 -preset slow -crf 21 -maxrate 12M -bufsize 24M -pix_fmt yuv420p -movflags +faststart <tmp>/final_tt.mp4. Выйдет около 45 МБ на 30 с, на глаз без потерь. Дальше работай с final_tt.mp4.
  - Звук: node ads/video/tools/cues.js … > cues.json → python3 -I ads/video/tools/sfx.py cues.json sfx.wav → python3 -I ads/video/tools/mix.py … Делай версию --nomusic и, если есть трек, версию с музыкой.
- Команда в обычном режиме обрывается через 2 минуты (с явным timeout — максимум 10 минут). Всё, что дольше 2 минут (черновик, финал, длинные куски), запускай в фоне (run_in_background) и жди завершения. Если долго — не перезапускай.
- MB=4: кадр k — среднее 4 подкадров в моменты k/30 − 1/60, k/30 − 1/120, k/30 и k/30 + 1/120 (окно вокруг кадра, а не позади него).
  - Что должно быть на кадре k на 100%, держи на всём окне от k/30 − 1/60 до k/30 + 1/120.
  - Удар: HIT(k) — это кадр доли минус 25 мс, поэтому на кадре доли удар уже полный.
  - Вспышка 100% на 2 полных кадра: белый от HIT(k) до кадра доли + 0.045 с (около 70 мс).
  - Ровно один кадр k (глитч): окно [k/30 − 0.02, k/30 + 0.0125).
  - Кадры ударов и пики вспышек проверяй на рендере MB=4, а не на черновике.

6.5 Жёсткие правила (каждое выучено на ошибке)
1) Зоны текста. Буквы считаются без свечения и при ПИКОВОМ масштабе (наезды, пружины, punch-in):
   - x 90…990, y 440…1420;
   - ниже y 900 — x не дальше 940 (справа кнопки TikTok); строка по центру там не шире 800 px;
   - выше y 900 строка по центру не шире 900 px;
   - y 250–420 — место для подписи-стикера, анимированный текст туда не заходит.
2) В words() для строк по центру ставь ls:false. Анимация межбуквенного интервала выталкивает первое слово за край.
3) Ни одного кадра на запасном шрифте. Перед каждым долгим рендером запускай fontcheck.js.
4) MB=4 усредняет 4 подкадра. Если объект за один подкадр сдвигается больше своего размера, вместо смаза видно 3–4 копии. Как лечить:
   - блюр по скорости внутри страницы: spd → feGaussianBlur stdDeviation "0 N", делённый на масштаб;
   - мягче пик скорости: inOutSine, окна 0.35–0.45 с;
   - ограничить уход: tz не больше 900, opacity (1−q)², blur не больше 40 px;
   - для самых быстрых кусков — MB=8.
5) Следующий элемент входит только после того, как ушёл предыдущий. Иначе в кадре каша.
6) Bloom съедает тёмный текст на светлом фоне: такие элементы рисуй поверх bloom. Белое пятно за словом съедает буквы — подкрась его и сделай слабее.
7) Детерминизм. Перерендерь кусок через FROM/TO и сравни с полным рендером. Разница должна быть только шумом кодека: PSNR от 38 дБ.
8) Картинки и фото — только свои (нарисованные кодом) или с лицензией на коммерческое использование. Источник запиши в отчёт.

7. ПРОВЕРКА КАЧЕСТВА (повторяй цикл, пока не станет чисто)
После каждого рендера:
- Контактный лист: ffmpeg -i X -vf 'fps=2,scale=216:-2,tile=10x8' -frames:v 1 sheet.png (80 кадров = 40 с). Открой и посмотри.
- Стоп-кадры: кадр 0, последний кадр, каждый удар, каждый переход (±2 кадра), каждая строка в момент наибольшего масштаба. Открывай и смотри глазами.
- Полоски кадров 10–15 к/с вокруг каждого перехода. Проверь: нет серых и мутных кадров стыка, сцены не накладываются, нет двойных копий.
- Яркость по кадрам (ffmpeg signalstats):
  - кадр 0: YAVG не ниже 70;
  - нет провалов в серое (SATAVG резко ниже соседних кадров);
  - места, где YDIF почти ноль дольше 0.4 с вне окна breath, посмотри глазами: допустим только медленный дрейф от 2% в секунду;
  - вспышки (скачок YAVG вверх больше чем на ~40 за кадр): не больше 3 за любую 1 с.
- Зоны текста: textcheck.js проходит все кадры с шагом 1/30.
  - Рамки букв бери через Range.getClientRects() по текстовым узлам, плюс window.TEXTBOX. Не бери getBoundingClientRect контейнера: у div по центру это вся ширина 0…1080. getClientRects даёт строку с запасом шрифта сверху и снизу, поэтому проверка чуть строже, чем по буквам: это нормально.
  - Проверяй только читаемую фазу: итоговая opacity (произведение по всем предкам) не меньше 0.5, blur меньше 4 px (CSS blur и stdDeviation смаз-фильтра), t не в окне free.
  - Печатай нарушения: t, текст, рамка.
- Контраст: стоп-кадр каждой цветной заливки — слово читается, контраст не ниже 3:1 (п.3.1).
- Синхрон:
  - прогони beats.py по звуку готового mp4 — доли должны совпасть с сеткой в пределах ±15 мс;
  - на рендере MB=4 пик каждого удара стоит на кадре floor(TB(k)*30) или на кадр раньше.
- Звук: ebur128 — I = −14 ±0.5 LUFS (только SFX: −20 ±1), true peak не выше −1.5 dBTP.
- Файл: ffprobe — h264 1080x1920 30 к/с + aac 48000 Гц стерео, размер до ~50 МБ (п.6.4). Битрейт звука не проверяй: на редких SFX AAC сам даёт меньше 192k.
- Петля: PSNR первого и последнего кадра не меньше 30 дБ. От удара ответа до конца — 6 долей, без пустых пауз (п.3.7).
- Тексты: нет опечаток, у фактов есть источники, у чисел есть единицы.
Составь список «прошло / не прошло». Исправь всё из «не прошло». Перерендери изменённые куски (MB=4 с FROM/TO) и проверь снова. Повторяй, пока список не станет чистым. Только после этого делай финал. До финала прогони куски MB=4 на всех быстрых местах (crash zoom, падения, вжики, расцвет петли): копии видны только там, а финал идёт 20 минут.
